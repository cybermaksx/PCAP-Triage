# Гайд по рефакторингу PCAP-Triage

Пошаговый план перехода от одного файла на 190 строк к структуре
«один проход → факты → детекторы → вывод».

Код здесь **не дописан намеренно**. Везде, где стоит `# TODO`, ты пишешь сам —
в основном это перенос твоего же существующего кода на новое место.
Заготовки показывают только структуру и форму данных.

**Время:** шаги 0–6 (собственно рефакторинг) — примерно 1.5 часа.
Шаги 7–10 (новая функциональность) — ещё около часа, можно в другой день.

---

## Что получится в итоге

```
PCAP-Triage/
├── main.py           ~50 строк   CLI и оркестрация
├── context.py        ~70 строк   сбор фактов за один проход
├── detectors.py      ~80 строк   детекты + пороги + список DETECTORS
├── report.py         ~60 строк   печать в консоль и экспорт JSON
├── requirements.txt
├── .gitignore
├── tests/
│   └── test_detectors.py
├── test.pcapng
├── README.md
└── LICENSE
```

Направление зависимостей — только в одну сторону. Это важно, иначе получишь
циклические импорты:

```
main.py ──> context.py
        ──> detectors.py ──> (ничего, кроме стандартной библиотеки)
        ──> report.py    ──> (ничего)
```

`context.py` **не знает** о существовании детекторов.
`detectors.py` **не знает**, откуда взялся `Context` — он просто читает его поля.
`report.py` **не знает** ни о том, ни о другом — он получает готовые данные.

---

## Главное правило

> **Рефакторинг не меняет поведение программы.**

Шаги 0–6 не должны добавить ни одной новой функции. На вход тот же файл — на
выходе тот же текст. Если после шага 6 вывод отличается, значит ты что-то сломал,
и надо чинить, а не «ну наверное так даже лучше».

Новая функциональность начинается только с шага 7, когда старая уже проверена.

Причина простая: если менять структуру и поведение одновременно, то при поломке
ты не поймёшь, из-за чего она — из-за переезда кода или из-за новой логики.

его на шаг 7.)

- `@property` — это способ сделать так, чтобы `ctx.avg_size` работало как

  чинит реальный баг: сейчас ты не различаешь «один хост сканирует 100 портов на
  одной машине» и «один хост стучится в один порт на 100 машинах». Первое —
  вертикальный скан, второе — сетевой sweep, это разные атаки.
- `self.counts['ipv6']` — заполнять пока **не надо**, оставь 0. Это изменение
  поведения (сейчас IPv6 падает в `other`), займёшься после шага 6.
- `arp_table` тоже пока не заполняй — это для шага 7.

## Шаг 5. `main.py` — оркестрация (10 минут)

От файла на 190 строк остаётся около 50.

### Заготовка

```python
import argparse
import sys

from scapy.all import rdpcap

from context import Context
from detectors import DETECTORS
import report


def parse_args():
    parser = argparse.ArgumentParser(
        description="PCAP-Triage — offline pcap analysis and threat hunting"
    )
    parser.add_argument("pcap_file", help="path to the .pcap/.pcapng file")
    # TODO (шаг 8): --json PATH
    # TODO (шаг 8): --threshold N
    return parser.parse_args()


def main():
    args = parse_args()

    print("Reading the pcap file ...")

    # TODO: чтение файла с обработкой ошибок
    #   FileNotFoundError    -> файла нет
    #   PermissionError      -> нет прав на чтение
    #   Scapy_Exception      -> файл есть, но это не pcap
    # В каждом случае: понятное сообщение в stderr и sys.exit(1).
    # НЕ голый traceback — пользователь не должен видеть стек scapy.
    packets = rdpcap(args.pcap_file)

    print(f"Loaded {len(packets)} packets\n")

    # Этап 1: один проход, собираем факты
    ctx = Context()
    for idx, pkt in enumerate(packets):
        ctx.feed(pkt, idx)

    # Этап 2: прогоняем детекторы по собранным фактам
    findings = []
    for detect in DETECTORS:
        findings.extend(detect(ctx))

    # Этап 3: вывод
    report.print_stats(ctx)
    report.print_findings(findings)

    print("\n Analysis complete!")


if __name__ == "__main__":
    main()
```

### Подсказки

- Исключение scapy импортируется так: `from scapy.error import Scapy_Exception`
- Сообщения об ошибках — в `sys.stderr`, а не в `stdout`:
  `print("...", file=sys.stderr)`. Это стандарт для CLI: тогда `python main.py x > out.txt`
  сохранит отчёт, а ошибку покажет на экране.
- Строку `print("Generating report... (coming soon)")` пока оставь — она есть в
  baseline. Уберёшь на шаге 8, когда JSON заработает по-настоящему.
- Обрати внимание: `main()` не знает, какие есть детекторы. Он просто берёт
  список и прогоняет. Именно поэтому добавление Modbus не потребует правок здесь.

### Про `rdpcap` и `PcapReader`

Не меняй `rdpcap` на `PcapReader` на этом шаге, хотя соблазн есть.

Причина: `PcapReader` — итератор, у него нет `len()`, поэтому строка
`Loaded N packets` перед анализом станет невозможна (количество ты узнаешь только
после прохода). Это изменение вывода → сломает сверку на шаге 6.

Переход на потоковое чтение сделай **отдельным коммитом** после шага 6. Одно
изменение за раз.

## Шаг 7. Детектор ARP-спуфинга (20 минут)

Первый детектор, написанный сразу в новой структуре. Здесь ты проверишь, что
архитектура действительно работает.

### Идея

MITM нельзя задетектить напрямую — детектируется механизм. При ARP-спуфинге
атакующий рассылает ARP-ответы, где чужой IP сопоставлен с его собственным MAC.
Значит признак: **один IP-адрес заявлен с разных MAC-адресов**.

### Что делать

1. В `Context.__init__` поле `arp_table` уже есть.
2. В `Context.feed` заполни его: `ip -> set(mac)`.
   Нужные поля scapy: `pkt[ARP].psrc` — IP отправителя, `pkt[ARP].hwsrc` — его MAC.
3. В `detectors.py` напиши `detect_arp_spoof(ctx)`.
4. Добавь имя функции в список `DETECTORS`.
5. `main.py` и `report.py` **не трогай**. Если пришлось — значит где-то нарушена
   развязка, разберись где.

### Вопросы, на которые стоит ответить самому

- Учитывать все ARP-пакеты или только ответы (`pkt[ARP].op == 2`)? Чем отличается
  запрос от ответа с точки зрения спуфинга?
- Какой `severity` поставить? Подумай: спуфинг — это активная атака в процессе,
  а не разведка.
- Когда «один IP с двух MAC» — это **не** атака? Подсказка: длинный захват и
  переезд DHCP-аренды, отказоустойчивый кластер с VRRP, замена сетевой карты.
  Это твои false positives — про них стоит написать в `description`.
- Стоит ли ловить обратный случай — **один MAC заявляет много IP**? Что это значит?

### Проверка

У тебя в `test.pcapng` ноль ARP-пакетов, так что детектор ничего не найдёт.
Варианты проверки:

- собрать свой захват: `sudo tcpdump -i <интерфейс> -w arp.pcap arp`, параллельно
  подождать обычного ARP-трафика в сети;
- честнее и быстрее — юнит-тест на шаге 9: собираешь `Context` руками, без файла.

### Заодно

Раз baseline больше не нужен, сделай отложенные изменения:

- `"No SYN scanning detected"` → `"No threats detected"`
- печать множеств через `sorted(...)` — детерминированный вывод
- счётчик `ipv6` — заполни его наконец (`IPv6 in pkt`), чтобы IPv6-трафик
  перестал молча падать в `other`
- DNS поверх TCP — сейчас считается только UDP

Каждое — отдельным коммитом.

## Шаг 8. JSON-экспорт (15 минут)

Флаг `--json out.json`. Реализуй `export_json` в `report.py`.

### Форма файла

```json
{
  "file": "test.pcapng",
  "analyzed_at": "2026-08-11T18:30:00",
  "statistics": {
    "total_packets": 40,
    "protocols": {"tcp": 25, "udp": 6, "...": 0},
    "unique_ips": ["8.219.122.25", "..."],
    "unique_ports": [53, 443, "..."],
    "packet_size": {"avg": 270, "min": 54, "max": 2894}
  },
  "findings": [
    {"type": "PORT_SCAN", "severity": "HIGH", "...": "..."}
  ]
}
```

### Ловушка

`json.dumps` не умеет сериализовать `set` — упадёт с `TypeError`. Твои
`unique_ips` и `unique_ports` — множества. Преврати в отсортированные списки:
это и чинит ошибку, и делает вывод детерминированным.

### Зачем это вообще

Тул, который только красиво печатает в консоль, — тупик: его нельзя встроить
ни во что. Тул, отдающий JSON, встраивается в чужой пайплайн одной командой
`| jq '.findings[] | select(.severity=="HIGH")'`. Именно JSON-вывод отличает
скрипт от инструмента.

Заодно добавь `--threshold N`, чтобы порог SYN-скана задавался из CLI, а не
константой в коде.

### Главная мысль

Тесты детекторов **не должны читать pcap-файлы**. Ты собираешь `Context` руками:

```python
from context import Context
from detectors import detect_syn_scan


def test_syn_scan_detected_above_threshold():
    ctx = Context()
    ctx.syn_targets[('10.0.0.66', '10.0.0.5')] = set(range(1, 50))

    findings = detect_syn_scan(ctx, threshold=20)

    assert len(findings) == 1
    assert findings[0]['type'] == 'PORT_SCAN'
    assert findings[0]['src'] == '10.0.0.66'
```

Вот ради этого и делался весь рефакторинг. В старом коде такой тест написать
было нельзя: `threat_checking` требовал список настоящих пакетов и печатал в
консоль.

## Ловушки

**Циклический импорт.** Если `context.py` импортирует `detectors.py`, а тот
обратно — Python упадёт с `ImportError`. Держи направление: `main` → всё
остальное, и никогда наоборот.

**print внутри детектора.** Самый частый срыв. Хочется быстро посмотреть, что
получилось, и написать `print` прямо в `detect_*`. Такой детектор ломает
JSON-режим и не тестируется. Отлаживай через `return` и `pytest -s`, или через
временный `print` в `main()`.

**Два изменения сразу.** «Заодно поменяю rdpcap на PcapReader» — и вот уже
непонятно, из-за чего сломалось. Один коммит — одно изменение.

**Мутабельность и `setdefault`.** `ctx.syn_targets.setdefault(key, set()).add(port)`
работает потому, что `setdefault` возвращает **ссылку** на множество, и `.add`
меняет его на месте. Если случайно напишешь `ports = ctx.syn_targets.get(key, set())`
без последующей записи обратно — данные потеряются молча.

**Дублирование в счётчиках.** В старом коде `elif ICMP in packet` стоит внутри
блока `if IP in packet` — то есть ICMP считается только для IPv4. При переносе
легко случайно поменять `elif` на `if` и получить другие числа. Тогда `diff` на
шаге 6 покажет расхождение — не игнорируй его.

## Если застрял

- **На переносе кода** — исходник целиком доступен из git, файл никуда не делся:
  `git show HEAD:main.py` (последний коммит) или `git show main:main.py`
  (версия до всех правок, в ветке `main`).
- **На `@property`** — сделай обычным методом, разберёшься позже. Не блокируйся
  на синтаксисе.
- **На обработке ошибок scapy** — поставь голый `except Exception as e` и уточни
  типы потом. Главное, чтобы пользователь видел сообщение, а не стек.
- **Всё сломалось** — `git checkout -- .` откатит незакоммиченное. Ветка `main`
  с рабочей версией никуда не делась.
